## Result

H: starts with the complete directory tree, original names and sizes, and
the same creation-date semantics as the former eager installer. The first
DOS open fetches immutable `file.<sha256-prefix>.bin` contents through the
existing bounded Asyncify transport. Successful contents are cached once,
including identical aliases. Full SHA-256 verification precedes the private
EXEC reference; editing, renaming, truncating or replacing the guest file
does not mutate that reference or revive stale contents. Failed downloads
return DOS error 5, leave the metadata intact, and permit a working retry.
The real F3 test displays the first line of `H:\SRC\VC.ASM`.

Eager startup files are 4.99.09's `VC.COM` and `VC.OVL` reconstructed from
their linked images, plus `VC.INI`, `VC.EXT` and `VCEDIT.EXT`. `VC.HLP` and
other shipped contents are lazy. Native Linux and door files remain fully
embedded; those builds do not invoke Emscripten or download anything.

The complete page's separately gzipped startup payloads total **922,580
bytes**, down from **1,299,288**: **376,708 bytes saved**. The gate prints the
reduction and enforces both the 150,000-byte saving and 1,300,000-byte cap.
There are 14 lazy program modules and 54 immutable file-content payloads
(1,025,342 uncompressed bytes), excluded from first load.

Linux installs the unchanged older executable as `VC405.COM` beside the
other config-directory programs, so `vc405` starts it. Browser and door
users press Enter on `H:\VC405\VC.COM`; setup is `H:\VC405\VCSETUP.COM`.
F3 and F10 use the actual older code, and F10 returns to the newer VC.
Both older programs inspect `VC=` for their settings directory. Their
private environment selects `$XDG_CONFIG_HOME/vc-linux/VC405` on Linux
(default `~/.config/vc-linux/VC405`) or `H:\VC405` in browser/door mode.
Tests save through both programs and verify that 4.99.09's INI is unchanged.
Renamed byte-identical copies also run; ordinary Linux `vc` and `vcsetup`
host commands retain their meaning.

## Three weaknesses of this implementation

1. `runtime/web_files.c:94`: preserving inode metadata requires direct
   MEMFS `contents`/`usedBytes` manipulation and operation wrappers. This
   depends on Emscripten internals and needs revalidation on SDK upgrades.
2. `Makefile:339`: startup linear memory rises from 64 to 80 MiB to retain
   every module and private file reference with checked headroom. The
   network saving does not make this a low-memory browser implementation.
3. `runtime/dos_core.c:1425`: the configuration adapter refuses a short DOS
   directory longer than 65 characters. Deep Linux config paths can still
   prevent 4.05 from starting; no additional short-path indirection is
   provided for that case.
