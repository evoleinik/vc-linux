# Games for the browser build

**Type:** Decision doc
**Status:** building
**Date:** 2026-10-01

## Goal

Eugene asked on 2026-10-01: "what games can we ship with it". Today `H:\GAMES` holds only a joke
file.

## Criteria, fixed before the options

1. **Same story.** A game is translated from its own assembly, exactly like VC. No emulator.
2. **Licence.** The source must be released under a licence that lets us ship it.
3. **Runs on what we have.** Text mode at B800h, INT 16h keys, the BIOS timer. No graphics modes.
4. **Fun in 30 seconds**, with no manual.
5. **Instant.** Small enough not to slow the page.

## Eugene's reply, 2026-10-01

Asked to pick among A, B and "Bootle first", he wrote: "can we find some abandonware". He also
said yes to a PC speaker in the page.

Abandonware is still under copyright, so it fails criterion 2 on a public site. Two famous
text-mode classics were released by their owners, though (checked 2026-10-01):

- **ZZT** (Tim Sweeney, 1991). Epic made the full registered game and its worlds freeware on
  10 October 1997. asie's 2020 Reconstruction of ZZT is Turbo Pascal source that compiles to the
  identical ZZT.EXE, released under MIT with Epic's permission.
- **Kroz** (Scott Miller, 1987 to 1990). Apogee made the series freeware in March 2009 and released
  the Turbo Pascal source under GPL-2.0-or-later.

Both are compiled Pascal, so no assembly listing exists. That adds an option:

| Option | Strongest objection | Fails when |
|---|---|---|
| E. ZZT and Kroz, translated from their EXE files. A new front end finds instructions by following code from the entry point and every procedure in the compiler's map file, instead of reading a listing. | Bigger than A. The runtime also needs timer interrupts delivered at dispatch boundaries, since ZZT plays music from INT 8, and Turbo Pascal's `Delay` busy loop may need care. | Code reached only through a computed jump the walk cannot see. Unicorn tracing can find those before translation. |

## Eugene's second reply, 2026-10-01

Asked to pick between ZZT and the small games, he wrote: "is there quickbasic the basic".

QBasic and QuickBASIC were never released. Microsoft still owns them, and the QB64 project is a
separate reimplementation. Their ancestor is free, though (checked 2026-10-01):

- **GW-BASIC.** Microsoft released the 1983 8088 assembly source under MIT on 21 May 2020. TK
  Chia's fork (codeberg.org/tkchia/GW-BASIC, MIT) adds the missing OEM modules and assembles with
  JWasm, the assembler this project already uses. Its author calls the interpreter "mostly
  working". Serial port I/O is still stubbed.
- **The games for it.** David Ahl's *BASIC Computer Games* (1978): Star Trek, Hunt the Wumpus,
  Lunar Lander, Hammurabi and about a hundred more, all plain text. Ahl placed all his works in
  the public domain on 15 June 2022.

| Option | Strongest objection | Fails when |
|---|---|---|
| F. GW-BASIC translated through the existing JWasm path, with Ahl's games on H:. | A 60 KB interpreter is bigger than VC's code, and "mostly working" means some bugs are upstream's. BASIC's SOUND, PLAY and ON TIMER want the PC speaker and timer interrupts. | GW-BASIC uses a trick the translator has not met, such as code it writes at run time. |

## Recommendation

A. Every game runs through the same translator and runtime as VC, and VC launches it with Enter,
as on DOS. That makes the toy a demo of the translator, not of VC alone.

What would change the ranking. If Eugene wants a "wow" game more than a set of small ones,
B's cubicDoom wins. If the NASM reader turns out large, converting five 512-byte sources to MASM
syntax by hand is the cheaper path.

## Outcome — 2026-10-01

Built by codex from `docs/briefs/11-gwbasic.md`, reviewed, then fixed from
`docs/briefs/13-gwbasic-fixes.md`. Evidence for every planted defect is in `docs/verification/`.

- `GWBASIC.EXE` is a real 51,296-byte file. VC starts it with DOS EXEC, which reads the file and
  runs the translation whose bytes match. A renamed copy runs, and a changed one gets a DOS error.
- The translator now places 39 module listings by the link map. 63,680 distinct instructions in
  VC and GW-BASIC pass the unicorn gate. VC's generated C stayed byte-identical.
- GW-BASIC needed timer interrupts, including its 400 Hz sound timer. It also needed Ctrl-Break,
  the PIT and speaker ports, DOS 1.x FCB calls and correct "not supported" BIOS answers.
- Twelve of Ahl's games reach their first prompt. In Chromium, Enter on `STARTREK.BAS` started
  Super Star Trek, and `LRS` worked.
- `PLAY "CDE"` sounds at 1047 Hz for C. That is GW-BASIC's own 1983 table: octave 6 starts at
  4186 Hz, and octave 4 divides it by four.
- The wasm grew 58%, to 1.55 MB gzipped. The first VC screen still appears in about 250 ms
  locally.

A Claude review found three majors, all fixed with tests that failed first. A BASIC `CALL` into
untranslated code now stops only GW-BASIC. VC.COM and VC.OVL never depend on the installed files,
which are now written atomically. Typed commands reach Linux again unless they name a translated
program, and `gwbasic` never falls back to the shell. A codex review was blocked by OpenAI's
security content filter and produced nothing.

## Turtle graphics, asked 2026-10-01

Eugene asked: "can we have turtle graphics/logo writer". LogoWriter (LCSI, 1986) was never
released, so it fails criterion 2. What is free (checked 2026-10-01):

- **bootLogo** by Oscar Toledo G. (2024, BSD-2, COM build). A real Logo in 512 bytes: `FD`, `BK`,
  `RT`, `LT`, nested `REPEAT [...]`, `PU`, `PD`, `SETCOLOR` and `TO ... END` procedures. NASM
  source. It draws in CGA mode 4 (320×200, four colours) through BIOS INT 10h.
- **GW-BASIC's own graphics**, already shipped: `SCREEN 1`, then `DRAW "TA45 U20"`, `LINE`,
  `CIRCLE` and `PSET`. `DRAW` is close to a turtle.

Both need the one thing the runtime lacks: a graphics screen. Today the BIOS layer renders text
mode only.

| Option | Strongest objection | Fails when |
|---|---|---|
| G. CGA graphics (modes 4, 5, 6) in the BIOS layer, plus bootLogo translated through a new NASM listing reader. Browser: a canvas replaces xterm.js while a graphics mode is on. Terminal: Unicode braille dots, 2×4 per cell. | Two new pieces at once: a pixel screen in two front ends, and a second assembler. Braille in a terminal is a sketch of the picture, not the picture. | A program writes CGA memory in a way the renderer misses, such as palette or border tricks. |
| H. Graphics in the browser only. The terminal says "graphics mode" and waits. | Breaks the rule that both builds run the same programs. | Linux users press Enter on LOGO.COM. |
| I. A Logo written in GW-BASIC, using `DRAW`. | Not a real Logo, and we would be writing it. Still needs graphics. | Always, against criterion 1's spirit. |

Recommendation: G. One graphics layer unlocks bootLogo and every GW-BASIC graphics program, and
the NASM reader unlocks Toledo's other games (Bootle, Bricks, bootRogue). It also opens
cubicDoom later, which needs mode 13h on top of this.

Eugene, 2026-10-01: G, bootLogo with CGA graphics in both builds.

## Decision — 2026-10-01 (turtle graphics)

G. CGA modes 4, 5 and 6 in the BIOS layer, a canvas in the browser and braille in terminals, and
a NASM listing reader for bootLogo.

## A text editor, asked 2026-10-01

Eugene asked: "how about lexicon text editor". Лексикон (Е. Н. Веселов, ВЦ АН СССР, 1985; later
Микроинформ and Арсенал) was always proprietary. Early versions were handed out free of charge,
but nobody ever licensed it for redistribution or published its source. So it fails criterion 2.

What is free (checked 2026-10-01):

- **VZ Editor 1.6** by c.mos (Village Center, Japan). The famous fast DOS editor, 29 modules of
  8086 assembly, released as BSD-3 at github.com/vcraftjp/VZEditor in late 2024. It ships a US
  build for plain IBM PCs (`VZ-IBM/US/VZUS.COM`). Its README says nobody had found a free
  assembler that builds it. Our JWasm assembles 25 of 29 modules cleanly with `-Zm -DUS` once
  include names are matched case-insensitively. The other four have 9 errors: a mixed-case
  include, anonymous `@@` labels and two syntax forms.

| Option | Strongest objection | Fails when |
|---|---|---|
| J. VZ Editor US build, translated like GW-BASIC, and made F4's editor in the browser. | Japanese-first program; its English messages and help may be thin. A 29-module link we must get byte-identical to the shipped `VZUS.COM`. | It needs a BIOS or DOS call our runtime lacks, such as EMS for big files. |
| K. EDLIN from Microsoft's MIT MS-DOS sources. | A line editor. Funny, not useful. | Anyone tries to edit a file. |
| L. No DOS editor. Keep `$EDITOR` on Linux and the browser's "no editor" message. | The browser keeps a dead F4. | A visitor presses F4. |

Recommendation: J. It gives the browser its first editor and keeps the "translated, not emulated"
rule. Matching the shipped `VZUS.COM` byte for byte proves our build of it is right.

Eugene, 2026-10-01: J, VZ Editor, built after Logo lands so the two BIOS changes do not collide.

## Decision — 2026-10-01 (editor)

J. The VZ Editor US build, translated, installed next to GW-BASIC, and F4's editor in the browser.

## Ranking of everything else, asked 2026-10-01

Eugene asked: "what other software can we run. can you rank it".

Criteria, fixed before ranking:
1. Legal to ship on a public site.
2. Cost: assembly source our assemblers build is cheap. Compiled Pascal or C needs a new
   front end that reads a compiler's map, which is expensive.
3. Runs on our machine: text mode, CGA once Logo lands. VGA mode 13h is new work.
4. Fun or useful to a visitor within 30 seconds.

One limit applies to every option. Only programs translated ahead of time can run, because
there is no emulator. So DEBUG's `G`, or anything assembled inside the toy, cannot run.

| Rank | Software | Licence, source | Strongest objection | Fails when |
|---|---|---|---|---|
| 1 | VZ Editor (decided, after Logo) | BSD-3, 8086 asm | Japanese-first program | It needs EMS for big files |
| 2 | COMMAND.COM from MS-DOS 2.0 or 4.0, plus EDLIN, MORE, FIND, SORT, TREE, MEM | MIT (Microsoft, 2014/2018 and 2024), 8086 asm | Old MASM dialect; the 4.0 build expects DOS-hosted tools | VC's EXEC of COMSPEC meets a COMMAND.COM path our DOS lacks |
| 3 | Toledo's text games: Bootle, Bricks, bootRogue, Lights, bootBASIC | BSD-2, NASM | Each is a 512-byte toy | Bootle never exits, so it needs the stop key |
| 4 | cubicDoom | BSD-2, NASM | Needs VGA mode 13h and a 256-colour palette on top of CGA | Terminals: braille cannot show its shading |
| 5 | ZZT, then Kroz | Freeware; ZZT reconstruction MIT, Kroz GPL-2; Turbo Pascal | Needs the compiled-EXE front end. ZZT also plays music from INT 8 | Code reached only through a computed call the walk misses |
| 6 | Sopwith; Rogue 5.4 with PDCurses | GPL (2003) and BSD; C plus some asm | Needs a 16-bit C compiler (OpenWatcom) and the compiled-code front end | The compiler's output uses a runtime call our DOS lacks |

Not possible: Лексикон, LogoWriter, QBasic and QuickBASIC, Norton Commander and abandonware in
general, because none is licensed for redistribution.

Recommendation: 1, then 2. COMMAND.COM turns the browser's "no shell" into a real DOS prompt
and keeps every piece Microsoft's own code. Then 3, which the NASM reader from Logo makes cheap.

What would change the ranking. If JWasm cannot build COMMAND.COM without large patches, 3
overtakes 2. If Eugene wants one famous game more than tools, 5 (ZZT) jumps to second, at the
highest cost on the list.
