## Implementation

`build/vc --door` uses only H:, seeded from the browser's shared `demo_files`
generator: 42 files, 811,645 bytes. VC's own setup/program files additionally
live in hidden `.VC` under the private drive. The shipped ordinary/browser
`data/VC.INI` is unchanged; the door-specific generated configuration starts
both panels at H: and initially hides internal entries.

The original node-pty process runs DOS. A detached janitor creates the
0700 node-named session, watches its lifetime pipe/carrier/deadline, removes
the tree without following symlinks, and restores the terminal. The default
limit is 60 minutes; positive fractional minutes support short tests. Direct
Rogue startup never opens VC panels and exits with the game.

Host command/editor dispatch is refused centrally. DOS filesystem operations
are descriptor-anchored beneath H:, reject links/special files, and enforce
an aggregate 8 MiB logical-file quota including sparse writes, truncation,
FCB writes, and open-but-unlinked files. VZ's private swap stays on H: and
releases quota after normal or aborted editing. The modem phonebook stays
empty across reset. Door mode suppresses host logs/screen dumps, kitty,
modifyOtherKeys, and mouse requests; ordinary native behavior is preserved.

## Three remaining weaknesses

1. The 8 MiB limit counts logical regular-file bytes, not empty-file inodes,
   directory metadata, or filesystem allocation overhead
   (`runtime/dos_fs.c:339`). It is not a complete host-storage resource limit.
2. Every caller runs as the same UID/GID 65534
   (`infra/bbs/doors/run-door.sh:40`). Separation relies on runtime path
   confinement, not separate Unix identities or per-session kernel namespaces.
3. If terminal output is completely full, the final timeout notice is best
   effort and can be lost (`runtime/door.c:198`). Cleanup and exit deliberately
   take precedence over waiting indefinitely for a disconnected reader.

### Review fixes

A focused review found three more gaps. Each got a test that failed first.

**1a. The worker could kill its janitor.** Both run as the same uid. The
worker could aim SIGIO, as SIGKILL, at the janitor with `F_SETOWN`,
`F_SETSIG` and `O_ASYNC` on stdin.

- Red: the `sigio-janitor` hook armed it and exited 0 instead of dying. A
  separate run confirmed the harm: 3 s after the worker exited, its session
  `node-23-...` was still there, because the janitor was dead.
- Fix: Landlock ABI 6 signal scoping (`scoped = LANDLOCK_SCOPE_SIGNAL`). Since
  this box has ABI 4, seccomp also kills `fcntl` `F_SETOWN`, `F_SETOWN_EX`
  and `F_SETSIG`. Plain `kill` to another PID was already a seccomp kill.
- Green: the hook dies with SIGSYS before arming, and the janitor cleans up.
  The two Landlock-only tests (`kill` and SIGIO, with seccomp switched off in
  the test binary) are skipped here: "running kernel has Landlock ABI 4;
  signal scoping needs ABI 6". Run them on axis.

**1b. Closing the lifetime pipe stopped the janitor.**

- Red: the `close-lifetime` hook closed the pipe and slept. The janitor
  cleaned up and left at once, and the worker was still alive after 6 s.
- Fix: an orderly exit now writes one byte, `D`, and never waits for the
  janitor. That byte only tells the janitor to leave the terminal alone. The
  pipe closes when the worker exits. If the worker is still the janitor's
  parent 500 ms after the pipe closes, the janitor sends SIGTERM, then SIGKILL
  after 1 s, as on timeout, and only then cleans up.
- Green: the worker dies by SIGTERM within the test's 6 s and the session is
  removed.
- Consequence: the janitor now always outlives its worker, so it is reaped by
  PID 1. ENiGMA's PID 1 is `pm2-runtime`, which does not reap adopted
  children. So `enigma.yaml` now sets `shareProcessNamespace: true`, making
  pause PID 1. Before this change the same zombie already appeared after every
  hangup and timeout. A test checks the setting: removing it fails 1 test.
- `tests/test_door_cleanup.c` now runs its worker as a separate process
  under a subreaper, as the BBS would be.

**2. Merged MCB sizes could wrap.** Three free `M` blocks: m before a, a and
b of 7FFFh paragraphs, b at a+8000h.

- Red: `test_door_memory --merge-wrap` was killed by SIGALRM after 2 s.
- Fix: a block, or two blocks being merged, that ends past FFFFh is a broken
  chain (error 7), in `mcb_merge` and in `mem_free_owned`.
- Green: AH=48h returns error 7 and AH=4Ch returns; the fuzz stays clean.

**3. tmpfs pages.** The quota now charges each file its size rounded up to
whole pages (4 KiB, or the system page size if larger).

- Red: in a new test, 4,032 one-byte files all fitted, and the files
  allocated 16,515,072 bytes on this box's tmpfs `/tmp`.
- Green: exactly 2,048 fit, the next write is disk full, and they allocate
  at most 8 MiB. Older byte-exact tests in `test_dos_fs.c`,
  `test_dos_exec.c` and the GW-BASIC e2e test now count pages.
- Sizing: 2 doors × `nodeMax 4` × 8 MiB = 64 MiB, half of the 128 MiB
  `emptyDir`. A packaging test parses all three numbers. Shrinking
  `sizeLimit` to 64Mi fails it. The README states the arithmetic.
